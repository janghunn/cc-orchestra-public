# Historical gate tabulation

A row is one concrete design, implementation-diff, or post-merge finding whose disposition can be traced. The 19-column CSV is the canonical record; the four marked blocks below are generated from it. `design` means a pre-implementation brief or plan correction, `diff` means the task's own diff, and `post-merge` means a defect found after its introducing task finished. `rejected` denotes a rebutted finding and is excluded from effectiveness counts. The inventory includes all 44 read task directories and explicit exclusions from `self-hosting-36/.orchestra/36-gate-tabulation-ab-design/evidence/corpus.txt`.

The five core diff gates are `lead-diff-review`, `codex-verify`, `codex-review`, `claude-verifier-opus`, and `claude-verifier-normal`; the design core gate is `codex-plan-review`. Other reporter tokens are `lead-plan`, `codex-intake`, `codex-audit`, `codex-orchestrator`, `implementer-self-test`, `orchestrator`, `user`, and `later-task:<id>/<gate>`. An `@rN` suffix identifies a gate round. Each core gate is recorded in exactly one of reported, ran without a report, or not run for each row; `missed_then_caught` records earlier misses by a gate that eventually reported the finding. A later-task report is separate from the introducing task's gate partition. Codex-prefixed reporters count as Codex; lead, Claude verifier, and orchestrator reporters count as Claude; `user` counts as human; self-test inherits the implementer family. For a later-task token, the family is the underlying gate's family. The `confidence` column distinguishes retained round evidence from summary-only or ambiguous attribution.

Set `GATE_AB_ROOT` to another copy of the historical corpus if needed, then run `python3 eval/gate-ab/recount.py check` from this repository. The script validates CSV schemas, gate partitions, source paths, inventory counts, and all generated Markdown blocks.
